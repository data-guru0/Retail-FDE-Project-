# Scenario 03 — AI-generated "damage" photo → escalate

**Route:** escalate **· Automated by:** manual (needs an AI-generated image) **· Group:** decision behaviour **· [demo]**

## What this shows

A synthetic "damage" photo is flagged by a local AI-image detector. It is **one**
signal that pushes the case to a human — never, on its own, an auto-denial.

## The situation

A customer files a return citing damage and uploads a photorealistic image of a
cracked product that was actually generated by an image model, not taken with a
camera.

## Run it

The detector (`haywoodsloan/ai-image-detector-deploy`, chosen by the bake-off in
`ml/detector_bakeoff/`) is lazy-loaded on the first image check.

1. Get an AI-generated product image. The bake-off harness produces real ones:
   ```bash
   docker compose run --rm worker python -m ml.detector_bakeoff.run
   # AI samples land in ml/detector_bakeoff/sample/ai/
   ```
2. In the shop, buy a product, start a return with reason **Damaged**, and upload
   one of those AI images.
3. Open the case in the dashboard.

## What happens, step by step

| # | Node | What it does here | What you see |
|---|---|---|---|
| 1–4 | data_quality → planner → intake → policy | as normal; photo present, `image` in the plan, `get_order` + `check_policy` via ContextForge, `policy_version` recorded | tool calls `ok=true` |
| 5 | **image** | CLIP similarity may even be *plausible* (the fake looks like the product), **but** the AI-image detector returns a high `ai_generated_score`. Both numbers go into the Image node output | `ai_generated_score` high, `detector` = the model id |
| 6 | **behavior** | risk model + history + ring check | `risk_score` |
| 7 | **decision** | a damage claim backed by a photo that looks synthetic is not something to approve → **escalate**, citing the detector score as one factor among the signals | `decision = escalate` |
| 8 | **critic** | concurs | `veto = false` |
| 9 | **explanation** | neutral wording for the customer ("a specialist will review the photos") | text saved |
| 10 | **GovernanceGate** | proposed = `escalate` → **escalate**. The detector score alone could never produce a `deny` here — auto-deny is impossible by construction | `route = escalate` |

## What to check afterwards

```bash
docker compose exec -T postgres psql -U returnguard -d returnguard -c \
 "select parsed_output->>'ai_generated_score' ai, parsed_output->>'clip_similarity' clip
  from agent_runs where agent='image' order by created_at desc limit 1;"
```

- **Dashboard → case detail:** the Image evidence block shows both the CLIP score
  and the AI-generated probability.
- **Langfuse:** the Image node has no LLM call unless CLIP was borderline; the
  detector runs locally on CPU (no API cost).

## Why it matters

One model's opinion is never the verdict. The detector is a strong hint, wired in
as a factor the Decision agent weighs and a human confirms — not a kill switch on
the customer's refund.
